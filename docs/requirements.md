# 요구사항

## 확정 사항

### 목적과 인터페이스

- 소프트웨어 엔지니어가 DB 인덱스, 소프트웨어 디자인·아키텍처 등 하나의 백엔드 주제를 단계별로 공부하는 개인 학습 도구다.
- 프런트엔드 개발 부담을 줄이기 위해 TUI를 사용한다. 별도 웹 UI나 네이티브 앱 UI는 결정된 범위에 없다.
- 화면에서 자료를 볼 수 있어야 하며, 인쇄용 PDF 내보내기는 필수다.

### 과정과 파트

- 시작 시 주제, 학습 목표, 범위를 정하고 기본 과정의 완료 지점을 둔다.
- 한 파트는 30~45분 분량이며 개념, 동작 원리, 실무 예시, 시각자료, 퀴즈를 포함한다.
- 파트 끝에는 관련 심화 주제와 그 주제를 공부할 이유를 후속 학습 후보로 제시한다.
- 심화 주제는 사용자가 선택해 별도 후속 학습으로 진행한다. 기본 과정을 자동으로 끝없이 확장하지 않는다.

### 시각자료와 PDF

- 시각자료는 필수다. 개념별 다이어그램, SVG, 필요한 생성 이미지·삽화를 적절히 혼합한다.
- Mermaid, draw.io 등 도구를 상황에 맞게 사용할 수 있다. 모든 도구의 동시 구현을 요구하지 않는다.
- 본문과 그림의 설명을 연결한다. 화면·인쇄에서 글자 크기, 선명도, 페이지 나눔, 한글, 흑백 가독성을 고려한다.
- PDF에 학습 본문, 시각자료, 퀴즈 문제를 포함한다. 정답은 문제와 분리해 풀이 전에 보이지 않게 구성한다.

### 퀴즈

- 간단한 이해도 체크 용도다. 출제 → 사용자 풀이 → 정답 바로 확인 → 사용자 복습/다음 선택으로 진행한다.
- 앱에서 답을 입력하거나 종이에서 풀 수 있다. 사용자가 원하면 정답을 바로 확인한다.
- 복습하거나 다음 파트로 갈지는 사용자가 직접 판단한다.
- 자동 채점, AI 답안 평가, 점수 통과 조건, 강제 재시험, 적응형 보충 과정은 범위에서 제외한다.

### 기본 흐름

1. 주제 입력
2. 범위·학습 목표 설정
3. 파트별 학습 자료·시각자료 생성
4. 화면/PDF 열람·인쇄
5. 이해도 체크 퀴즈 풀이·정답 확인
6. 사용자 복습/다음 선택
7. 기본 과정 완료
8. 사용자가 선택한 심화 주제로 후속 학습

## 미정 선택과 제안

- **정식 이름:** `study-tui`는 임시 작업명이다.
- **주제 발견:** 직접 입력 외에 이력서 경험에서 주제를 찾는 방식도 후보이다.
- **화면 열람:** TUI에서 PDF·이미지 미리보기를 여는 방식을 제안했으며 구체적인 방식은 미정이다.
- **초기 구조:** 별도 백엔드 서버 없이 TUI, 내부 학습 로직, 외부 AI·웹 검색 연동, 로컬 저장, PDF 생성을 하나의 로컬 프로그램에 두는 초안이다.
- **구현 언어·라이브러리:** 언어와 TUI 라이브러리는 미정이다.
- **AI·검색:** 공급자, 모델, 인증 방식, 비용 예산은 미정이다.
- **저장·내보내기:** 로컬 저장 형식, PDF 생성 도구, 시각자료 생성 도구는 미정이다.
